# 非程序员也能推进的 YangAgent 路线图

这份文档面向不熟悉编程、AI、Revit API 的使用者。

## 1. 你只需要理解三件事

### pyRevit 是试验区

pyRevit 适合快速做按钮、快速验证想法。

适合：

- 导出报告。
- 检查模型。
- dry-run 预览。
- 小范围内部工具。

### `.addin + .dll` 是正式插件

C# DLL 插件适合长期使用、正式部署、复杂界面和受控修改模型。

适合：

- 公司正式工具箱。
- 多版本 Revit 支持。
- 更稳定的 UI。
- 更严格的事务和权限控制。

### AI 是开发助手，不是直接操作者

AI 可以帮你写代码、查问题、生成报告和方案，但真实模型修改必须：

1. 先预览。
2. 再确认。
3. 再执行。
4. 最后留日志。

## 2. 推荐双轨路线

```text
需求想法
  -> pyRevit 快速验证
  -> 测试模型确认有用
  -> C# .addin + .dll 正式化
  -> 公司部署
```

## 4. 你如何参与

你不需要写代码，只需要提供这些信息：

- 你想自动化什么。
- 当前手工怎么做。
- 哪些操作不能自动做。
- 输出想要 Excel、Markdown 还是 Revit 弹窗。
- 测试模型里跑出来的结果是否符合预期。

## 5. 每个功能的安全等级

### 低风险

- 导出数据。
- 生成报告。
- 统计数量。
- 检查缺失参数。

### 中风险

- 批量填写空参数。
- 批量重命名视图。
- 批量创建图纸。

### 高风险

- 删除元素。
- 修改中心文件。
- 批量重编号。
- 操作链接模型。
- 保存或同步模型。

高风险功能必须先经过测试模型验证。

## 6. 判断功能是否可以正式化

一个 pyRevit 功能满足以下条件后，才迁移到 C# 插件：

- 至少在 2 个测试模型运行成功。
- 用户确认输出结果有价值。
- BIM 负责人确认规则合理。
- 没有误改模型风险。
- 有清晰的 dry-run 和日志。

## 7. 当前优先级

1. 继续完善 pyRevit 报告工具。
2. 建立 Revit 2027 C# 插件骨架。
3. 把设置界面正式化。
4. 把成熟报告工具迁移到 DLL。
5. 再考虑真正写模型的功能。
