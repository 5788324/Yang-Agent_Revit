# 项目初期安全工作预案 (Security & Backup Preparations)

在项目初期，为了防止代码丢失、敏感数据泄露以及在测试自动化脚本时损坏公司正式项目，需落实以下安全准备工作：

## 1. 代码资产安全与 Git 规范

为防止团队开发时的代码冲突或误删：
* **每日提交**：所有脚本和文档的修改，每日结束前必须提交 (Commit) 到本地 Git 并推送到远程仓库。
* **分支策略**：
  * `main` 分支保持绝对稳定，仅存放经过测试的、安全的只读/dry-run 工具。
  * 任何高风险的新功能（如批量删除、参数修改）必须在 `feature/*` 分支上开发。
* **敏感信息脱敏**：**严禁**将任何 API 密钥（如 OpenAI Key、Anthropic Key）、公司真实项目文件（`.rvt`）提交到 Git 仓库中。请利用 `.gitignore` 将它们拦截在外。

## 2. 数据隐私与大模型交互边界

由于我们将使用 LLM 协助开发和分析：
* **禁止直连图纸**：在把 Revit 导出的 JSON/CSV 交给 AI 分析时，请确保数据中不包含涉及客户机密的敏感几何数据或国防/涉密项目的名称。
* **私有化服务优先**：对于核心项目的参数分析，尽量使用公司内部合规的 AI 服务；如果不具备条件，在将数据发送至公有云 LLM 时，必须先进行数据脱敏。

## 3. Revit 测试沙盒建立

禁止直接在公司生产服务器（如 BIM 360 或共享盘上的中心文件）运行处于开发阶段的 AI Agent。
* **建立沙盒模型**：必须在本地准备几个体积小、但元素齐全的“测试沙盒模型” (`sandbox_architecture.rvt`, `sandbox_mep.rvt`)。
* **分离模型**：即便必须使用真实项目测试，也必须“脱离中心模型 (Detach from Central)”并另存到本地临时目录。

## 4. 故障演练与回滚准备

* **测试事务回滚**：在编写任何 `Transaction` 代码时，主动测试抛出异常的场景，确保 Revit 的“撤销”按钮能一次性干净地撤销 Agent 执行的所有操作。
* **版本回退**：团队成员应熟悉 `git checkout` 或 `git revert` 命令。如果某次发布导致 Revit 崩溃，能够在一分钟内回退到上一个稳定版本的 pyRevit 工具。
